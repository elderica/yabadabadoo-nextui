Yabadabadoo 0.3 for NextUI, package release 1: a Sega Saturn pak (tag `SATURN`) for
`tg5040` (TrimUI Smart Pro, Brick, Brick Hammer), `tg5050` (TrimUI Smart Pro S) and
`h700` (Anbernic RG35XX / RG40XX family).

This is an unofficial build from the elderica/Yabadabadoo fork, not a release of the
Yabadabadoo authors. Please report problems with it here, not upstream.

## Install

- **Pak Store:** install *SATURN*.
- **By hand:** extract `Yabadabadoo-NextUI-v0.3.0.1.zip` at the root of the SD card.

Then put a Saturn BIOS in `Bios/SATURN/` (`sega_101.bin`, Japan, or `mpr-17933.bin`,
USA/Europe) and games in `Roms/Sega Saturn (SATURN)/` (create the folder after a Pak
Store install). Formats: .cue with its .bin files, .chd, .iso, .mds, .ccd, .m3u, .zip.

## What's in this build

- The SH-2 recompiler for AArch64. It replaces the interpreter on these devices.
- Fixes to the recompiler code that the AArch64 and ARM (Miyoo Mini) builds share:
  NOT, SWAP, NEG and NEGC whose result is unused; TST #imm,R0 and CMP/EQ #imm,R0 with
  a constant R0; ADDV and SUBV; ADDC and SUBC setting T; DIV1 Rn,Rn; BRAF, BSRF, JMP
  and JSR with DIV1, MAC.L or MAC.W in the delay slot; registers moved between a
  branch and its delay slot; and when MACH, MACL and T are kept.
- MAC.L and MAC.W in saturation mode (S=1) follow the SH-2 manual's description: MAC.L
  limits the sum to 48 bits towards the sign of the product, and MAC.W limits MACL to
  32 bits and sets bit 0 of MACH on overflow. This applies to the interpreter as well.
  The manual's sample code saturates negative MAC.L sums to MACH = 0x00008000, and
  Yabadabadoo used to do the same.
- Save states keep the same size from the moment a game starts, so NextUI can resume a
  game after a power off. States no longer contain a picture of the screen. States
  made by earlier versions still load.

## Known differences from the hardware

**The order of the two memory reads of MAC.L and MAC.W.** `MAC.L @Rm+,@Rn+` and
`MAC.W @Rm+,@Rn+` read one operand at `Rm` and one at `Rn`. The SH-2 reads `@Rm` first,
as Mednafen does (its source notes the order as confirmed). Yabadabadoo reads `@Rn`
first, in the interpreter and in both recompilers. The product and the registers come
out the same. The order matters only when a read has a side effect, such as a read
from an I/O register or a FIFO; MAC operands are normally tables in RAM or ROM. We
know of no game that behaves differently because of it.

## Notes

- A real Saturn BIOS is required.
- Auto-resume states saved by test builds before this release don't load. Start the
  game again and save a new state.
- Tested in an emulated setup against the interpreter. Results on the devices are
  welcome as GitHub issues, with `.userdata/<platform>/logs/SATURN.txt`.
