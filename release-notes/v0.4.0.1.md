Yabadabadoo 0.4 for NextUI, package release 1: a Sega Saturn pak (tag `SATURN`) for
`tg5040` (TrimUI Smart Pro, Brick, Brick Hammer), `tg5050` (TrimUI Smart Pro S) and
`h700` (Anbernic RG35XX / RG40XX family).

**Pre-release.** Upstream's 0.4 changes have not been tried on these devices yet.

This is an unofficial build from the elderica/Yabadabadoo fork, not a release of the
Yabadabadoo authors. Please report problems with it here, not upstream.

## Install or update

- **Pak Store:** install or update *SATURN*.
- **By hand:** extract `Yabadabadoo-NextUI-v0.4.0.1.zip` at the root of the SD card,
  over v0.3.0.1 if you have it.

A Saturn BIOS goes in `Bios/SATURN/` (`sega_101.bin`, Japan, or `mpr-17933.bin`,
USA/Europe), and games in `Roms/Sega Saturn (SATURN)/` (create the folder after a Pak
Store install). Formats: .cue with its .bin files, .chd, .iso, .mds, .ccd, .m3u, .zip.

Save states of v0.3.0.1 load in this version, the auto-resume state after a power off
included.

## What's new

- **Yabadabadoo 0.4, "The Speed Update".** Most 3D games run faster, several 2D games
  with garbled sprites are fixed, and Virtua Fighter 2 no longer repeats a voice clip.
  See the [upstream release notes](https://github.com/ProRapSuperstarOriginalMaster/Yabadabadoo/releases/tag/v0.4).
  Its speed figures were measured on a Miyoo Mini+, not on these devices. The sound
  CPU change of 0.4 (the 68K runs after every tenth of a line, which fixes Vampire
  Savior's sound) is ported to the AArch64 recompiler.
- **Built with link-time optimisation** (upstream's `LTO=1`): the same frames as a
  plain build, and a core about a fifth smaller.
- **Fixed: MAC.L/MAC.W in the delay slot of a branch.** v0.3.0.1 lost the result
  of a MAC.L or MAC.W in the delay slot of a branch inside the same code block
  (BRA, BRAF), so an `STS MACL` at the target read a wrong value. One of v0.3.0.1's own
  recompiler fixes caused it; upstream Yabadabadoo never had it.

## Known differences from the hardware

**The order of the two memory reads of MAC.L and MAC.W.** `MAC.L @Rm+,@Rn+` and
`MAC.W @Rm+,@Rn+` read one operand at `Rm` and one at `Rn`. The SH-2 reads `@Rm` first,
as Mednafen does (its source notes the order as confirmed). Yabadabadoo reads `@Rn`
first, in the interpreter and in both recompilers. The product and the registers come
out the same. The order matters only when a read has a side effect, such as a read
from an I/O register or a FIFO; MAC operands are normally tables in RAM or ROM. We
know of no game that behaves differently because of it.

## Notes

- A real Saturn BIOS is required.
- Upstream reports that RetroArch's threaded video makes 0.4 skip frames on devices
  other than the Miyoo Mini. NextUI's frontend has no such setting, so it shouldn't
  apply here, but it isn't verified on these devices. If you see frames skipped
  with frameskip off, please say so in an issue.
- Tested in an emulated setup: random SH-2 programs, short programs for each fix,
  Panzer Dragoon and the BIOS boot, recompiler against interpreter. Results on the
  devices are welcome as GitHub issues, with `.userdata/<platform>/logs/SATURN.txt`.
