Yabadabadoo 0.4 for NextUI, package release 2: a Sega Saturn pak (tag `SATURN`) for
`tg5040` (TrimUI Smart Pro, Brick, Brick Hammer), `tg5050` (TrimUI Smart Pro S) and
`h700` (Anbernic RG35XX / RG40XX family).

This is an unofficial build from the elderica/Yabadabadoo fork, not a release of the
Yabadabadoo authors. Please report problems with it here, not upstream.

## Install or update

- **Pak Store:** install or update *SATURN*.
- **By hand:** extract `Yabadabadoo-NextUI-v0.4.0.2.zip` at the root of the SD card,
  over an earlier version if you have it.

A Saturn BIOS goes in `Bios/SATURN/` (`sega_101.bin`, Japan, or `mpr-17933.bin`,
USA/Europe), and games in `Roms/Sega Saturn (SATURN)/` (create the folder after a Pak
Store install). Formats: .cue with its .bin files, .chd, .iso, .mds, .ccd, .m3u, .zip.

Save states of v0.4.0.1 and v0.3.0.1 load in this version.

## What's new

- **Fixed: a crash in games that use the SH-2 cache as RAM.** Some games keep work
  data in the SH-2's on-chip cache (addresses `0xC0000000`-`0xC0000FFF`). The AArch64
  recompiler mapped that area with a truncated pointer, so the first access crashed
  the core (`Segmentation fault` in the log). NiGHTS into Dreams crashed this way
  right when a dream started, in v0.3.0.1 and v0.4.0.1. Thanks to zefas for the
  report. Upstream Yabadabadoo (32-bit ARM) never had this bug.

Everything else is as in v0.4.0.1; see its release notes.

## Notes

- A real Saturn BIOS is required. A bad BIOS dump can give a black screen at start.
- Testers confirmed NiGHTS into Dreams and other games on the devices. Tested in an
  emulated setup: NiGHTS into Dreams from the BIOS to gameplay (9000
  frames) gives the same frames as upstream's 32-bit ARM build; Cyber Doll gives the
  same frames as v0.4.0.1. Results on the devices are welcome as GitHub issues, with
  `.userdata/<platform>/logs/SATURN.txt`.
